# Chapitre 6 — Spécifications de myTravel

Un seul document : `specification-mytravel.docx`, la spécification complète de myTravel, écrite
pour être lue et modifiée **sans savoir coder**. Ce dossier ne contient aucun code, ne demande
aucune installation, aucune clé, aucun réseau. Le fichier s'ouvre dans Word, LibreOffice ou
Google Docs.

## Contenu du document

| Partie | Rôle |
|--------|------|
| Mode d'emploi | Qui écrit, qui relit, qui code ; ce qui est attendu de chacun ; les quatre règles d'or |
| Partie 1 — Vue d'ensemble | Cas d'usage, fonctionnalités, hors périmètre, contraintes, architecture, ordre de passage, vocabulaire |
| Partie 2 — Fiches des agents | La liste des outils et les dix fiches agents (mission, reçoit, produit, outils, attend, ne fait pas, en cas de panne) |
| Partie 3 — Règles d'acceptation | Les cinq règles R1 à R5 au format « Étant donné / Quand / Alors », avec exemples chiffrés |
| Partie 4 — Checklist de relecture | Les questions à passer avant de transmettre la spec aux développeurs, à cocher Oui / Non |
| Annexe A | Fiche agent vierge à copier |
| Annexe B | Règle d'acceptation vierge à copier |

Chaque partie commence par un encadré **« Ce qui est attendu dans cette partie »**.

## Comment s'en servir

1. Lis le mode d'emploi et la partie 1 d'une traite.
2. Pour un nouvel agent, copie la fiche de l'annexe A dans la partie 2 et remplis chaque case.
3. Pour une nouvelle règle, copie le bloc de l'annexe B dans la partie 3, avec un exemple chiffré.
4. Si tu as modifié une ligne « Attend », recalcule l'ordre de passage (partie 1, section 8).
5. Avant de transmettre, passe la checklist de la partie 4. Chaque « non » est un défaut.
